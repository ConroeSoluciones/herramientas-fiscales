# Agent instructions

- The repository is a pnpm workspace: the Nuxt 4.6 site uses the `app/` source directory, and the SIDOF scraper is isolated in `packages/sidof-scraper`.
- For Impeccable UI/design requests, default to the Nuxt frontend in `app/`; for landing-page reviews, use `app/pages/index.vue`. Treat `packages/*` as backend utilities and do not ask the user to choose among them unless they explicitly name a package.
- Tailwind CSS 4 is integrated with `@tailwindcss/vite`; `@nuxtjs/color-mode` adds persisted light/dark/system preferences, and the `dark:` variant follows the `.dark` class in `app/assets/css/main.css`. Nitro routes remain under root `server/api/`.
- The home page must feature Tipo de Cambio SAT as its primary card plus the SAT error finder. Its top widget calls `GET /api/tipo-cambio/penultimo`, which returns the second D1 row by publication date descending. `/tipo-de-cambio-dolar-mxn` includes a calendar and monthly history backed by `GET /api/tipo-cambio/historial?mes=AAAA-MM`.
- The SAT error finder flows from `/codigos-sat` (catalog index) to `/codigos-sat/[clave]` (all rows or search); legacy `/errores` routes redirect permanently. `GET /api/catalogos-error` returns summaries and `GET /api/catalogos-error/:clave?q=...` returns filtered rows. Keep DB access server-only.
- Keep SEO follow-ups in `docs/seo-pendientes.md`; revisit them in the next SEO-focused PR.
- Root commands: `pnpm dev`, `pnpm preview`, `pnpm deploy:cloudflare`, `pnpm d1:migrate:local`, `pnpm d1:migrate:remote`, `pnpm typecheck`, `pnpm lint`, `pnpm format:check`; ingestion commands are `pnpm db:backfill` (up to 60 recent notes), `pnpm db:sync` (insert only unseen `codNota`s), and `pnpm sat:catalogos:sync` (download, parse, and replace the configured SAT Excel catalogs monthly). Tests: `pnpm test:scraper`, `pnpm test:d1-client`, `pnpm test:ingestion`, `pnpm test:sat-catalogos`.
- Workspace package `dist/` files are built during install. If editing a package consumed by Nuxt, run `pnpm build:packages` before starting/restarting `pnpm dev`; avoid cleaning package `dist/` while Nuxt typechecking is watching it.
- Each page owns its `useSeoMeta` and canonical path. Keep visible breadcrumbs off pages unless explicitly requested.
- The site is a CSFacturación property under `https://www.csfacturacion.com`. `NUXT_PUBLIC_SITE_NAME` and `NUXT_PUBLIC_SITE_URL` are configured in `.env`; maintain the official logo, brand palette, and typography documented in `docs/identidad-visual-csfacturacion.md`.
- The app runs on the Cloudflare Workers Nitro preset and reads D1 through the `DB` binding. SQL schema changes belong in `migrations/` and must be applied with Wrangler.
- `packages/d1-client` provides the shared D1 interface and Cloudflare REST API client used by the Node-based ingestion commands and the no-binding fallback. Production Worker requests must use the D1 binding, not an API token.
- The scraper package's SIDOF source POSTs to `/busqueda/cargaNotas/` for the first 10 results, then fetches `/notas/{codNota}` sequentially. Preserve parser tests if upstream responses change; do not hardcode browser cookies.
- `packages/sidof-scraper` only fetches/parses; `packages/sidof-ingestion` stores SIDOF records in D1. The daily scheduler itself is not configured yet; never run a timer inside the Nuxt web process.
- `packages/sat-error-catalogs` downloads, parses, and replaces SAT error catalog rows in D1; its monthly schedule is external and not configured yet. Sources are in `config/sat-error-catalogs.json`; never run a timer inside the Nuxt web process.
- SAT catalog XLS headers are on row 2; Nómina omits `ELEMENTO`/`ATRIBUTO` and uses `REGLA DE VALIDACIÓN`/`DESCRIPCIÓN DEL ERROR`, while several sheets call the description `ERROR`. Preserve `ACLARACIONES`, skip section rows without a code, and keep the schema migration to `TEXT` for long attributes such as CCE165.
